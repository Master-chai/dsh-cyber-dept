# 员工沟通使用说明

先打开当前会话的 IT 侧栏，在办公室或团队成员中选择员工，展开“员工介绍”，在工牌下方使用“沟通”。等待快照同步完成；只读预览或团队负责人不在线时按钮禁用。灰色按钮可悬停查看原因。

| 功能 | 怎么用 | 实际效果 |
| --- | --- | --- |
| 发消息 | 选成员 → 发消息 → 输入内容 → 确认发送 | 以本团队负责人身份投递给成员。负责人不能给自己发送；离线但已就绪成员允许投递，交由 DSH 处理。发送成功不表示任务已完成。 |
| 重开任务 | 在任务看板选中具体已完成任务 → 员工介绍 → 重开任务 → 确认 | 恢复待办并清除原负责人。需要继续执行时重新派活，再发消息通知。存在多条已完成任务时，必须先选中一条，避免误重开。 |
| 派活 | 选目标成员 → 派活 → 新建任务并填写标题/描述，或从下拉框选已有任务 → 确认 | 新建走“创建 + 指派”；已有任务只指派，不重复创建。勾选“指派后立即执行”会在指派成功后通知成员执行。依赖未完成的待办任务不可指派。 |
| 立即执行 | 展开看板中的已指派任务 → 立即执行 → 确认 | 向当前负责人发送执行指令，由 DSH 调度。已完成、未指派、依赖未完成或负责人为 lead 的任务不能直接执行。投递成功不代表已经开始或完成。 |
| 删除任务 | 展开任务看板中的具体任务 → 删除任务 → 确认 | 删除 DSH 原生任务，看板同步移除；有其他未删除任务依赖它时禁止删除。删除不打断正在执行的成员，需要停止时另行打断。 |
| 打断 | 选正在思考、输出、执行工具或等待审批的成员 → 打断 → 确认 | 请求停止该成员当前回合，保留已产生输出。空闲、离线或负责人自己不可打断。不会自动把任务标记完成或重新派活。 |

如果当前任务正在进行，任务按钮显示“完成任务”，它只修改任务看板状态，不打断员工执行。

## 失败后如何处理

- **任务版本已过期**：刷新，重新选择任务，再决定是否操作；插件不会强制覆盖新状态。
- **任务保留在看板，指派未完成**：不要再创建任务。刷新后选择目标成员，在“派活”的任务下拉框选择这项已有任务。
- **任务已指派，执行指令失败或结果待确认**：指派结果会保留。先查看成员会话，确认没有收到指令后，再从看板执行；不要重复创建任务。
- **结果未知 / 超时 / 断线**：操作可能已经发生。先检查目标会话、任务归属与状态，再决定下一步；错误框保留操作编号，插件不自动重试。
- **同一命令正在处理**：等待并刷新。宿主限时停止等待不等于取消了实际写入；相同操作编号在尚未结束时不会再执行。去重记录只在当前宿主进程的有限缓存内有效，不是永久业务去重。

这次更新同时包含宿主代码，完整加载请重启 DSH，然后打开 IT 侧栏。测试使用模拟服务，没有向真实成员发送消息、派活或打断。
